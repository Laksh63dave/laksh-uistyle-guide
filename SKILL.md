# Laksh Apple UI Guide

A reusable web design skill created by Laksh Dave.

## Purpose

Use this skill to design, build, or refine clean, premium, and carefully considered web interfaces inspired by Apple's approach to simplicity and visual consistency.

This is a design system, not a fixed website template. Adapt it to the product's identity, audience, content, and requirements.

## Workflow

1. Understand the website's purpose, audience, content, and required functionality.
2. Review `references/design-system.md` before making design decisions.
3. Establish a consistent colour palette, typography scale, spacing system, and layout structure.
4. Build clear visual hierarchy using whitespace, alignment, contrast, and restrained colour.
5. Create consistent components with refined borders, corner radii, and intentional interaction states.
6. Make the interface responsive across desktop, tablet, and mobile.
7. Add subtle animations only when they improve the experience.
8. Test usability, accessibility, visual consistency, and functionality.

## Design Rules

- Prioritise clarity, simplicity, and visual hierarchy.
- Use whitespace intentionally.
- Maintain consistent spacing and alignment.
- Use restrained accent colours.
- Prefer subtle borders over excessive shadows.
- Use rounded corners consistently.
- Keep typography readable and purposeful.
- Make buttons, links, and interactive elements clearly identifiable.
- Design responsive layouts rather than shrinking desktop layouts.
- Respect reduced-motion preferences.

## Avoid

- Random gradients and decorative blobs.
- Excessive glassmorphism.
- Repetitive cards without a clear purpose.
- Unnecessary animations and transitions.
- Arbitrary spacing and inconsistent typography.
- Fake dashboards, meaningless statistics, and placeholder content.
- Visual effects that reduce readability or usability.
- Generic AI-generated layouts that lack product-specific decisions.

## Implementation Guidance

- Inspect the existing project before changing it.
- Preserve the existing technology stack unless a change is necessary.
- Do not rebuild working sections without a reason.
- Keep HTML, CSS, and JavaScript maintainable.
- Use semantic HTML and accessible interaction patterns.
- Test the final interface at multiple viewport sizes.
- Prioritise performance and functional correctness alongside visual quality.
